# Architecture

`src/engine/` owns canonical signal samples, calibration maths, lead derivation, and measurement calculations. It does not import React. `generateLeadSignals()` creates I and II from shared event timing, derives III/aVR/aVL/aVF algebraically, and creates V1–V6 from explicit educational morphology profiles using the same noise/time arrays. `src/main.tsx` owns machine state and SVG presentation. Display settings transform coordinates only; they do not mutate source samples. The morphology remains a synthetic educational template, not validated patient physiology.

Renderer coordinates share `src/engine/calibration.ts`: 4 SVG user units represent one logical millimetre, x derives from paper speed, and y derives from gain. A one-millivolt calibration pulse and every trace use these same transforms. `PREVIEW_CSS_PIXELS_PER_SVG_UNIT` (0.8) is the explicit browser preview scale; viewport width in logical SVG units is measured from the container using that ratio, so responsive resizing changes the visible time window without stretching the waveform. CSS pixels are not physical millimetres; a physically sized print/export is not implemented.

`src/engine/clock.ts` owns simulated elapsed time. `SimulationClock` receives a request/cancel-frame scheduler, advances only by monotonic animation-frame timestamps (not frame count), is idempotent across repeated start calls, and exposes pause, resume, reset, visibility suspension and disposal. It discards a frame gap above 100 ms rather than drawing a catch-up sweep. This intentionally trades exact wall-time accounting during a long main-thread stall for avoiding a visibly large paper jump. Hidden tabs suspend and resume from the last displayed time. Unit tests inject a deterministic scheduler.

`src/components/LiveEcgMonitor.tsx` owns the browser lifecycle and renders a bounded rolling SVG window. `generateLeadWindow()` and `generateLeadSamples()` construct samples from absolute simulation timestamps using stateless seeded noise; negative timestamps provide past-only warm-up history at startup, while no sample later than the current clock time is generated. All lead series share sample indices, timestamps and event timing. A single-lead view generates only its selected lead (or I/II for a derived limb lead); the 12-lead view generates one shared window for all twelve. The 250 Hz source window is decimated only for SVG path display, at a density determined by the logical screen scale; a shared time-index phase retains the template's R-peak sample and keeps x-coordinates aligned. Multi-lead path updates are capped at 30 renders/second; single-lead updates follow animation frames. The source samples are not modified.

The trace head is fixed to the viewport's right edge. Each point is mapped with `timeMsToSvgUnits(sample.timeMs - elapsedMs, paperSpeed)` and `voltageMvToSvgUnits(sample.voltageMv, gain)`. The grid pattern's logical offset uses the same current paper position, so paper and trace move left together. Changing paper speed recalculates the visible time window and paper travel rate without resetting the clock; the current sweep head remains fixed. Gain changes only the vertical transform. There is one clock regardless of selected lead or layout.

Manual time points remain absolute milliseconds since playback reset. The result remains independent of gain, paper speed and display scale. Marker lines are drawn only while their absolute times fall inside the current rolling viewport; the numeric controls remain the keyboard-accessible alternative, and a note discloses when points are outside the visible strip. Reset also resets the active measurement's points; it preserves whether playback was paused or running. There is no automated wave-boundary detection and no drag-to-place caliper in this milestone.

The public integration boundary is planned as an `EcgLab` component accepting typed initial machine settings. It is not exported yet; the current app is a standalone checkpoint.

The UI theme uses CSS custom properties mapped to the live KYP light and dark palette: neutral blue-gray surfaces and text, cyan-teal primary controls, and low-contrast teal ECG grid lines. The standalone theme toggle persists its choice in `localStorage` under `ecg-lab-theme`; it does not access host application state.

`src/content/` is a framework-independent content-governance layer. `schema.ts` defines the discriminated Zod schemas and claim/review scope records, `references.ts` defines source-reference data, `types.ts` exports inferred record types, `validation.ts` separates structural validity from claim-level publication readiness and lifecycle transitions, `review-intake.ts` binds supplied review records to an exact content ID/version and declared scope, and `registry.ts` returns valid/published items while retaining rejected values and developer issues. `src/content/learn/` contains the ordered draft lesson and question records; `src/content/learn/registry.ts` applies the shared registry gate before exposing a published list.

`src/learn/` owns the Learn catalog, reusable typed lesson reader, formative checks, shared-engine demonstrations, and local progress. The catalog receives only `getPublishedLessons()` results and resolves only published linked questions. A lesson cannot be marked complete until all its sections are marked complete and its checks are attempted. `progress.ts` validates a versioned, no-PII local-storage format behind a small `LearnProgressStore` adapter boundary. No KYP authentication or service is used. Practice, Exam, and case-library interfaces have not been started.

Lesson calibration demonstrations call `src/engine/calibration.ts` and the existing deterministic signal generator. SVG user units represent logical millimetres (4 SVG units per logical millimetre); `PREVIEW_CSS_PIXELS_PER_SVG_UNIT` separately scales browser display. That ratio is not a guarantee of physical screen size, and print/export is not implemented.

Source/licensing, educational, medical-content, and publication approvals are distinct typed review records. Each identifies its record/version and scoped claim/reference IDs. Technical schema validation is an automated result, not a human approval. Publication readiness requires claim-level source mapping, actual scope coverage, current-version review metadata, a qualified medical reviewer for clinical records, permitted rights, and eligible dependencies. The software checks field presence; it does not authenticate identity, credentials, source truth, or legal rights. No published fixture is seeded because no genuine reviewer or approval data exists. See `LESSON_REVIEW_PACKETS.md`, `CLAIM_SOURCE_MATRIX.md`, and `CONTENT_REVIEW_WORKFLOW.md`.

Unit and React interaction tests for the engine, clock lifecycle, content model, lesson reader, knowledge checks, demonstrations, and progress run with Vitest. User-visible browser regressions live in `tests/e2e/` and run in Chromium with Playwright against an isolated Vite development server on port 4173. `scripts/test-e2e.mjs` owns startup/readiness/cleanup so the local runner exits cleanly on Windows as well as CI. Axe checks cover key simulator and Learn states in both themes/responsive sizes; these are supporting scans, not a complete accessibility certification. Tests observe controls through accessible roles and labels; the named, focusable live SVG viewport does not expose individual samples as separate screen-reader nodes.
