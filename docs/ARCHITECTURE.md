# Architecture

`src/engine/` owns canonical signal samples, calibration maths, lead derivation, and measurement calculations. It does not import React. `generateLeadSignals()` creates I and II from shared event timing, derives III/aVR/aVL/aVF algebraically, and creates V1–V6 from explicit educational morphology profiles using the same noise/time arrays. `src/main.tsx` owns machine state and SVG presentation. Display settings transform coordinates only; they do not mutate source samples. The morphology remains a synthetic educational template, not validated patient physiology.

Renderer coordinates share `src/engine/calibration.ts`: 4 SVG user units represent one logical millimetre, x derives from paper speed, and y derives from gain. A common viewBox width and amplitude-safe height are passed to the single trace and every lead row. The SVG preview is horizontally scrollable when its calibrated recording width exceeds the container. CSS pixels are a separate presentation scale, not physical millimetres; physical-size export is not implemented.

The public integration boundary is planned as an `EcgLab` component accepting typed initial machine settings. It is not exported yet; the current app is a standalone checkpoint.

The UI theme uses CSS custom properties mapped to the live KYP light and dark palette: neutral blue-gray surfaces and text, cyan-teal primary controls, and low-contrast teal ECG grid lines. The standalone theme toggle persists its choice in `localStorage` under `ecg-lab-theme`; it does not access host application state.

`src/content/` is a framework-independent content-governance layer. `schema.ts` defines the discriminated Zod schemas, `references.ts` defines source-reference data, `types.ts` exports inferred record types, `validation.ts` separates structural validity from publication readiness and lifecycle transitions, and `registry.ts` returns valid/published items while retaining rejected values and developer issues. `fixtures/` contains only explicitly labelled drafts. The React shell and signal engine do not import the registry; no Learn, Practice, Exam, or case-library interface has been started.

Source/licensing, educational, medical-content, and publication approvals are distinct typed review records. Technical schema validation is an automated result, not a human approval. Publication readiness is version-specific and requires the applicable gates; no published fixture is seeded because no genuine reviewer or approval data exists.

Unit tests for the signal engine and content model run with Vitest. User-visible browser regressions live in `tests/e2e/` and run in Chromium with Playwright against an isolated Vite development server on port 4173. `scripts/test-e2e.mjs` owns startup/readiness/cleanup so the local runner exits cleanly on Windows as well as CI. Axe checks run inside the browser suite for key light/dark and responsive states; these are supporting scans, not a complete accessibility certification. Tests observe controls through accessible roles and labels; named, focusable scroll regions make intentionally overflowing calibrated recordings keyboard reachable.
